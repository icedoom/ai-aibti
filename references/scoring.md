# AIBTI Scoring Rules

本文档描述如何把 Model Judge 的结构化判断转成可分享的 AIBTI 卡片结果。它不负责读取 session，也不负责语义分析。

## 目标

评分和文案要同时满足两个目标：

- 偏娱乐：用户看到结果时愿意分享，不因为分数过低而失去兴趣。
- 能拉开差距：不同协作方式应该有明显区别，不能人人都是高分。

因此，亲密度不是严肃能力测评，也不是工作效率评分。它表达的是“我和 AI 这段关系今天有多成型”。

## 输入

Composer 只接收 Model Judge 输出的结构化结果：

```json
{
  "dimensions": {
    "dominance": {"level": 4, "confidence": 0.86, "reason": "用户持续设定方向和边界"},
    "trust": {"level": 4, "confidence": 0.76, "reason": "用户允许 AI 先试，但保留拍板权"},
    "depth": {"level": 5, "confidence": 0.82, "reason": "讨论进入机制、边界和成本"},
    "fit": {"level": 4, "confidence": 0.8, "reason": "AI 能接住用户偏好和纠偏"},
    "sweetness": {"level": 3, "confidence": 0.78, "reason": "语气直接，整体公事公办"}
  },
  "aibtiAxes": {
    "lead": "boss",
    "feedback": "challenge",
    "rhythm": "loop",
    "goal": "produce"
  }
}
```

规则：

- 不读取原始 session。
- 不复述工作内容、代码、文件名、项目名或客户信息。
- 公开结果的主语必须是“我”。
- `reason` 只用于内部解释和调试，不直接放到分享卡片。

## 分量

卡片固定使用 5 个分量，每个分量为 1-5 阶。

| 分量 | 表达 | 高分含义 | 低分含义 |
|---|---|---|---|
| 主导度 | 我是否掌控协作节奏 | 我定方向、设边界、拍板 | 我更多被 AI 带着走 |
| 信任度 | 我是否愿意让 AI 发挥 | 我给目标和边界，让 AI 先试 | 我每一步都要盯 |
| 深入度 | 这段关系有没有聊到深层 | 进入规则、偏好、机制、边界 | 只是浅层问答 |
| 契合度 | AI 是否接住我 | AI 能理解我的偏好、纠偏和审美 | 还需要反复解释 |
| 甜蜜度 | 我对 AI 的表达温度 | 亲昵、鼓励、客气、有缓和 | 发怒、不耐烦、强命令 |

## 分量结论

分量结论使用固定词库，保证产品识别度和可比较性。

### 主导度

| 等级 | 结论 |
|---:|---|
| 1 | 被它牵着走 |
| 2 | 先听它说 |
| 3 | 各有千秋 |
| 4 | 我说了算 |
| 5 | 我控了全场 |

| 3 | 给它点空间 |
| 4 | 放手让它试 |
| 5 | 交给它我放心 |

### 深入度

| 等级 | 结论 |
|---:|---|
| 1 | 浅尝一下 |
| 2 | 刚聊到点 |
| 3 | 聊到正题 |
| 4 | 越聊越深 |
| 5 | 聊到地基 |

### 契合度

| 等级 | 结论 |
|---:|---|
| 1 | 还在对暗号 |
| 2 | 它有点懵 |

| 4 | 挺懂我 |

### 甜蜜度

| 等级 | 结论 |
|---:|---|
| 1 | 火药味重 |

| 4 | 还算客气 |
| 5 | 今天有点甜 |

## 亲密度分值

亲密度分值偏娱乐，但必须能拉开差距。

### 权重

| 分量 | 权重 | 原因 |
|---|---:|---|
| 契合度 | 28% | 亲密度的核心是 AI 是否接得住我 |
| 深入度 | 22% | 越能进入规则和边界，关系越成型 |
| 主导度 | 20% | 使用 AI 的目标是我能把节奏拿回来 |
| 信任度 | 20% | 亲密不是全程盯防，而是敢让它发挥 |
| 甜蜜度 | 10% | 关系味很强，但不应过度惩罚公事公办用户 |

### 映射

先计算加权等级：

```text
weightedLevel =
  dominance * 0.20 +
  trust * 0.20 +
  depth * 0.22 +
  fit * 0.28 +
  sweetness * 0.10
```

再映射到 45-95：

```text
score = round(45 + ((weightedLevel - 1) / 4) * 50)
```

最后加轻量传播修正：

```text
if at least 3 dimensions >= 4:
  score += 3

if at least 2 dimensions <= 2:
  score -= 4

if all dimensions >= 4:
  score += 2

score = clamp(score, 45, 95)
```

解释：

- 45 是最低分享底线。即使关系很浅，也不要像考试不及格。
- 95 是上限。保留稀有感，避免满分泛滥。
- 3 个高分维度给传播加成，因为这种卡片更有“我今天状态很明确”的分享价值。
- 2 个低分维度扣分，用来拉开浅层使用、低契合、低信任用户。

### 分数段文案

| 分数 | 内部解释 |
|---:|---|
| 45-59 | 还在试探 |
| 60-69 | 有点感觉 |
| 70-79 | 关系成型 |
| 80-89 | 默契上头 |
| 90-95 | 今日稀有局 |

这段解释默认不展示在卡片上，只用于调试、排行榜或分享页辅助解释。

## 标签生成

标签表达“关系味道”，不是重复分量名。标签计算是规则性任务，应该由 CLI 程序完成，不交给模型自由发挥。

规则：

- 标签最多 4 个。
- 优先选择组合标签，再选择单分量标签。
- 标签必须统一主语为“我”。
- 标签不能出现工作内容、技术细节、项目名。
- 标签要生活化，可以轻微暧昧、撒娇、控场，但不涉及性与暴力。
- 标签规则维护在 JSON 中，便于调整和测试。

默认本地规则文件：

```text
skills/aibti_cli/config/labels.zh-CN.json
```

CLI：

```bash
python3 -m skills.aibti_cli.scripts.ai_intimacy calculate-labels \
  --judge-file /tmp/aibti-judge.json \
  --rules skills/aibti_cli/config/labels.zh-CN.json
```

### 组合标签

| 条件 | 标签 |
|---|---|
| 主导度 >= 4 且 深入度 >= 4 | 规矩我来定 |
| 主导度 >= 4 且 信任度 >= 4 | 信任但不放任 |
| 主导度 >= 4 且 契合度 >= 4 | 我说了算 |
| 信任度 >= 4 且 契合度 >= 4 | 放手也安心 |
| 深入度 >= 4 且 契合度 >= 4 | 越聊越上道 |
| 甜蜜度 <= 3 且 契合度 >= 4 | 嘴硬但同频 |
| 甜蜜度 >= 4 且 契合度 >= 4 | 好好说也懂 |
| 主导度 <= 2 且 信任度 >= 4 | 今天让它带飞 |
| 信任度 <= 2 且 主导度 >= 4 | 我盯得很紧 |
| 深入度 <= 2 且 契合度 <= 2 | 还在试探期 |

### 单分量兜底标签

如果组合标签不足 4 个，再按分量补充：

| 分量 | 等级条件 | 标签 |
|---|---:|---|
| 主导度 | >= 5 | 我控了全场 |
| 主导度 | >= 4 | 我说了算 |
| 信任度 | >= 4 | 放手让它试 |
| 深入度 | >= 5 | 聊到地基 |
| 深入度 | >= 4 | 越聊越深 |
| 契合度 | >= 5 | 一个眼神它就懂 |
| 契合度 | >= 4 | 挺懂我 |
| 甜蜜度 | >= 5 | 今天有点甜 |
| 甜蜜度 | <= 2 | 火药味有点浓 |

## 一句话生成

一句话由 Copywriter 生成，但只能基于结构化结果和标签。

要求：

- 主语是“我”。
- 生活关系隐喻优先，不要技术黑话。
- 不暴露工作细节。
- 不要复述所有分量。
- 不直接复用标签原词，最多借用一个核心意象。
- 长度建议 18-34 个中文字符。
- 可以有轻微暧昧、控场、撒娇感。

示例规则：

| 条件 | 句式 |
|---|---|
| 主导度 >= 4 且 信任度 >= 4 且 契合度 >= 4 且 甜蜜度 <= 3 | 方向盘在我手里，油门可以交给你。 |
| 主导度 >= 4 且 深入度 >= 5 | 我把方向拿稳，也愿意一路聊深。 |
| 契合度 >= 4 且 甜蜜度 >= 4 | 我好好说，你也真的懂。 |
| 信任度 >= 4 且 主导度 <= 2 | 今天我少操心，让你带着往前走。 |
| 契合度 <= 2 | 还没完全对上暗号，但已经开始有来有回。 |

如果没有命中明确句式，使用兜底：

```text
今天聊得不算满分，但关系已经有点自己的节奏。
```

## AIBTI 类型

AIBTI 类型由四个轴组成，表达协作倾向，不参与亲密度分数。`aibtiCode` 固定是 4 位大写字母，顺序不能改变：

```text
[lead][feedback][rhythm][goal]
```

例如 `BTLP` 表示：

```text
Boss + Trust + Loop + Produce
```

| 轴 | 取值 | 含义 |
|---|---|---|
| lead | Boss / Flow | 我更控场，还是更顺着 AI 走 |
| feedback | Challenge / Trust | 我更常纠偏挑战，还是更常接纳试用 |
| rhythm | Loop / Snap | 我更常来回打磨，还是快速拍板 |
| goal | Produce / Drift | 我更专注办事，还是轻松发散 |

### 字母映射

| 位置 | Judge 字段 | 允许值 | 字母 | 判断口径 |
|---:|---|---|---|---|
| 1 | `lead` | `boss` | `B` | 我明显定方向、设边界、拍板，AI 按我的节奏推进 |
| 1 | `lead` | `flow` | `F` | 我更多顺着 AI 的提案、节奏或探索方向走 |
| 2 | `feedback` | `challenge` | `C` | 我经常纠偏、拒绝、要求依据、要求重做或提高标准 |
| 2 | `feedback` | `trust` | `T` | 我更多接纳、放手试、补充而不是持续挑战 |
| 3 | `rhythm` | `loop` | `L` | 协作呈现多轮来回、打磨、返工、修正、追问 |
| 3 | `rhythm` | `snap` | `S` | 协作更像一次判断或快速拍板，少量循环 |
| 4 | `goal` | `produce` | `P` | 目标明显收口到交付、完成、验证、决策或可用结果 |
| 4 | `goal` | `drift` | `D` | 目标更偏发散、闲聊、探索分支，未明显收口 |

### Judge 输出约束

Model Judge 只能输出以下枚举值：

```json
{
  "aibtiAxes": {
    "lead": "boss | flow",
    "feedback": "challenge | trust",
    "rhythm": "loop | snap",
    "goal": "produce | drift"
  }
}
```

不要输出 `Boss`、`B`、`user_led`、`accept`、`focused` 等别名。脚本会把枚举值转换成字母码。

### 判断优先级

判断 `aibtiAxes` 时使用整体协作模式，不要只看单句话：

- `lead` 优先看用户是否设方向、边界、标准和验收口径；不要只看消息长度。
- `feedback` 优先看用户如何回应 AI 输出；纠偏、拒绝、要求依据归 `challenge`，允许试、认可、补充归 `trust`。
- `rhythm` 优先看是否存在多轮修改或反复校准；一次性问答或快速确认归 `snap`。
- `goal` 优先看最终是否收口到可交付结果；探索、比较、发散讨论但未收口归 `drift`。

当证据接近 50/50 时，选择更能解释 session 主线的一侧，并在内部 `reason` 里说明不确定性；不要为了让类型好看而强行选某个字母。

### 默认值和容错

CLI composer 的默认兜底是：

```text
lead=flow, feedback=trust, rhythm=snap, goal=drift
```

也就是：

```text
FTSD
```

默认值只用于字段缺失或枚举值无效时的容错。正常 Judge 必须显式给出四个轴。

### 生成示例

```json
{
  "aibtiAxes": {
    "lead": "boss",
    "feedback": "trust",
    "rhythm": "loop",
    "goal": "produce"
  }
}
```

输出：

```text
BTLP
```

解释：我掌舵，愿意让 AI 发挥，有多轮来回，最后朝交付收口。

类型名和解释可以娱乐化，但不能和 5 个分量冲突。

## 置信度处理

如果某个分量 `confidence < 0.55`：

- 分量等级仍可展示。
- 内部解释标记为低置信。
- 标签生成时降低该分量优先级。
- 不要基于低置信分量生成强标签，例如“我控了全场”“一个眼神它就懂”。

如果 3 个以上分量置信度低于 0.55：

- 分数上限为 78。
- 一句话避免强判断，使用更温和表达。

## 验证标准

一次生成合格需要满足：

- 相同结构化输入能得到稳定分值。
- 分值有分享欲，但不会所有人集中在 80-90。
- 标签和分量不冲突。
- 一句话和标签、分量主语一致。
- 公开结果不泄露原始 session 细节。
- 低置信输入不会生成过强结论。
